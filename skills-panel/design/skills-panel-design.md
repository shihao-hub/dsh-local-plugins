# skills-panel 分组改造设计方案

> **状态：已实现。** 最终选定方案 B（单列 · 两级折叠），分组算法按实测结果落地为「来源层 + 命名空间自动聚类」。改动全部在 [client.js](../client.js)，行为由 [test-grouping.mjs](test-grouping.mjs) 验证（19 项断言全绿，真实目录 105 项零丢失）。实现说明见第 8 节。

面向 `@local/skills-panel`（`skills-panel/client.js`）的技能列表重排。配套设计稿：[skills-panel-design.html](skills-panel-design.html)（可直接在浏览器打开，折叠交互可点）。

---

> **修订记录（第二轮）**：初版把一级分组定为「系统内置 / 用户安装 / 项目级」，并假设 `skills/list` 的 `path` 能区分它们。**实测证明这个假设在你机器上不成立**：全部技能都来自同一个根，一级分组只会得到一个桶。后端机制、实测数据和改后的三级动态方案见第 2 节，其余章节不受影响。

## 1. 问题定义

现状是一张无结构的平铺列表：109 个技能，每个条目带 2~4 行描述加一个「查看 SKILL.md」，行高 60~80px。

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| 单条占高 | 62~80px | 26px（折叠态） |
| 同屏可见条数 | 约 8 | 约 24 |
| 定位任意技能 | 只能滚，平均 30+ 屏 | 折叠到类目，≤2 次点击或 1 次搜索 |
| 滚动条信息量 | 无 | 位置对应分组结构 |

**根因有两条，且是叠加的**：一是没有分组，滚动条不携带任何结构信息；二是行高按"信息完整"设计，而列表绝大多数时间只需要"认出是哪一个"。

只做分组不做密度，滚动问题只能解决一半——所以两个一起改。

## 2. 分组维度：能动态到什么程度

先回答"能不能动态"。分三档，越往后越依赖人工。

### 2.1 一级分组：来源 —— 后端本来就动态，但接口没给

翻了 `@deepseek-ai/dsh-skill-filesystem` 的契约后，实际的技能来源不是一个"系统 / 用户"二分，而是**五档 rank**（数字小者优先）：

| Rank | source 标签 | 路径 |
| --- | --- | --- |
| 100 | `project-dsh` | `<项目根>/.dsh/skills` |
| 200 | `project-agents` | `<项目根>/.agents/skills` |
| 300 | `custom` | `Config.customSkillDirs` |
| 400 | `user-dsh` | `~/.dsh/skills`（跳过其 `.system` 子目录） |
| 500 | `user-agents` | `~/.agents/skills` |
| 600 | `bundled` | `$DSH_BUNDLED_SKILL_DIR` |

另外还有**按包内置的 provider**，不落盘直接注册候选：`dsh-office`（office-docx / office-pptx / office-xlsx）、`dsh-badge`，以及带 ACL 诊断技能的那个 provider。它们的候选同样带 `source: "bundled"`。

关键点：**每个候选在发现阶段就已经打好了 `source` 和 `rank` 标签**，是注册表合并多个 provider 时用的。也就是说"来源"这件事后端本来就是动态算出来的，零人工表。

**但 `skills/list` 只透传了 5 个字段**（`name` / `description` / `whenToUse` / `modelInvocable` / `path`），`source`、`provider`、`rank` 全被截掉了。客户端只能看到路径。

**而你这台机器上，六个根里只存在一个**：

| Root | 存在 | 条目 |
| --- | --- | --- |
| `project-dsh` (100) | ✗ | — |
| `project-agents` (200) | ✗ | — |
| `custom` (300) | ✗ | — |
| `user-dsh` (400) | ✗ | — |
| `user-agents` (500) | ✓ | 105 |
| `bundled` (600) | 由环境变量决定 | — |

所以**一级按来源分组在你的现状下只会得到一个"用户安装 105"，纯属浪费一层**。它只在这样的场景里才划算：项目里放了 `.agents/skills`，或者同时挂着 `~/.dsh/skills` 和 `~/.agents/skills`。

> 想让来源分组真正可用且权威，需要 Host 在 `skills/list` 的返回里补 `source` / `provider` / `rank` 三个字段。这是 5 个字段变 8 个字段的小改动，但属于 Host 侧，不在这个插件里。

### 2.2 二级分组：功能 —— 可以自动长出 47%，但长不全

用 `design/verify-auto-cluster.py` 对你真实的 105 个技能名做过验证：**不提任何类目名**，只按 `-` 切段统计前缀覆盖，结果如下：

| 自动长出的分组 | 成员数 | 覆盖方式 |
| --- | --- | --- |
| `lark-*` | 28 | 名字自带命名空间 |
| `sh-agy-*` | 8 | 名字自带命名空间 |
| `redis-*` | 7 | 名字自带命名空间 |
| `sh-zed-*` | 6 | 名字自带命名空间 |
| 无共同前缀（兜底一桶） | 56 | 长不出来 |

**自动覆盖 49/105 = 47%，剩 56 项一个桶。** 这 56 项里包含两类东西：

1. 装技能的人用了不同习惯的名字（`sh-windows-*` 3 个、`sh-sublime-*` 2 个、`sh-github-*` 2 个……每个都不够 3 个，成不了簇）；
2. 一批**根本没有前缀**的基础技能（`code-review`、`tdd`、`grilling`、`research`……23 个）—— 这些正是随包附带的基础件，命名上刻意不带命名空间。

所以结论很明确：**纯动态的功能分组能拿到 47%，拿不到 100%**。剩下的要么靠人工表，要么靠技能自己声明。

### 2.3 因此采用三级方案（成本从零递增）

| 层级 | 分组依据 | 动态性 | 人工维护 |
| --- | --- | --- | --- |
| L1 来源 | 候选自带的 `source` | **完全动态**，后端已算好 | 零。需 Host 补 3 个字段；字段缺失时整层不渲染 |
| L2 命名空间 | 名字前缀自动成簇，≥3 个成员才成组 | **完全动态** | 零。`lark-*`、`sh-agy-*`……自动长出来 |
| L3 别名表 | 前缀 → 可读类目名 | 静态 | 一张 8~12 行的表，只为把 `sh-zed-` 显示成「Zed 编辑器」 |
| 兜底 | 以上都不命中 | — | 永远显示，绝不丢项 |

第 3 档还可以再动态一点：把「前缀 → 类目名」的表放进一个 JSON 配置文件（如 `<dshHome>/skills-panel.groups.json`），你改配置就改分组，不用碰代码。这样即使类目名需要人工起，也不需要在代码里维护。

**更好的长期解**：`SKILL.md` 的 frontmatter 本来就支持任意 `metadata`（契约里写明 optional `metadata`）。让 Host 读取 `metadata.category` 并透传，分类就彻底由技能自己声明、由生态自然演化，客户端一行表都不用。这是 Host 改动，建议作为第二步。

## 3. 行结构（已确认：紧凑默认 + 点击展开）

折叠态一行 26px，三段信息，右对齐标签：

```
[名称 monospace 12.5px/600]  [可选标签]  [描述 12px 单行省略号]
```

展开态（就地展开，不跳转）显示完整描述、「使用时机」和「查看 SKILL.md」：

```
┌────────────────────────────────────────────────┐
│  code-review                    用户可调用      │  ← 折叠态
└────────────────────────────────────────────────┘
┌────────────────────────────────────────────────┐  ← 展开态（details[open]）
│  code-review                    用户可调用      │
│  Review the changes since a fixed point …      │
│  使用时机  审阅分支、PR、进行中的改动。          │
│  查看 SKILL.md                                 │
└────────────────────────────────────────────────┘
```

用原生 `<details>/<summary>` 实现，键盘可达、`aria-expanded` 语义免费。

**关于标签位**：现在只有 `modelInvocable === false` 时显示「仅用户」。建议只保留**例外标记**（如「别名」「仅用户」），不给绝大多数普通技能加「用户可调用」这种默认值标签——那是给每一行都加噪声。设计稿里画的「用户可调用」是待你拍板的选项。

## 4. 分组交互

- **分组头 sticky**在滚动体顶部，折叠状态用左侧 chevron 旋转 90° 表达。
- **一级组只有在真的多于一个时才渲染**。来源字段缺失、或只有一个来源时，直接跳过 L1，让 L2 命名空间组升到顶层——避免出现"用户安装 105"这种占满一层却毫无信息量的标题。
- **默认展开状态**：L2 里成员最多的那一组展开，其余折叠；搜索框始终可见。这样默认视图约 1 屏内能看完全部结构，而不是 30 屏内容。
- **折叠状态记忆**：建议记住（存在插件内部 state，key 用 `sessionId` + 分组 id），面板切走再回来保持原样。理由：折叠动作表达了用户意图，复位会惩罚这个意图。
- **跳过「全部折叠 / 全部展开」按钮**：分组数量本来就少，逐组点击的成本远低于多一个常驻按钮的成本。设计稿 B 方案里画了，但建议砍掉（"出门前摘掉一件配饰"）。

## 5. 搜索

搜索是这个面板的第二个刚需——109 项里你绝大多数时候只找 1 个。

- 位置：头部下方常驻一行，占满宽度，右侧 `kbd` 提示快捷键。
- 过滤范围：名称 + 描述 + 使用时机，大小写不敏感；命中时**自动展开所有祖先分组**，并在匹配行上保留原始分组路径（显示"飞书 / Lark"来源小标）以便理解上下文。
- 空查询：恢复分组的默认折叠状态。
- 无结果：给出明确出口——「没有匹配"xxx"的技能」+ 一个「在全部 109 个技能中浏览」按钮清空查询，而不是留一句干巴巴的"无结果"。

## 7. 验收标准

实现后逐条核对（`design/test-grouping.mjs` 覆盖前 3 条与第 7 条的过滤部分）：

- [x] 所有技能一条不少地出现在某个分组里，兜底组可见。（真实 105 项，`every skill is accounted for` + `no skill appears twice` 双断言）
- [x] 只有一个来源时不渲染 L1；两个及以上来源必然渲染 L1。
- [x] 凑不满 3 个成员的前缀不生成分组，不进"幽灵组"。
- [x] **默认至少展开一组，且展开的不是兜底组**（`the default open group is not ns:other`）。
- [x] 折叠态单行 26px，描述溢出用省略号，不换行不撑高。（`summary` 用 flex + `text-overflow:ellipsis`）
- [x] 键盘：分组头与技能行都是原生 `button` / `details`，Tab 可达、Enter 可切换。
- [x] 搜索命中时自动展开全部祖先分组，并就地展开命中行。

- [x] 无会话 / 加载中 / 加载失败 / 空列表四个状态的文案与现状一致。

## 8. 实现说明（第 6 节列出的待确认项已全部拍板）

拍板结果：

1. **L3 别名表**：不引入配置文件。标签直接从名字前缀推导（`lark-` → Lark、`sh-zed-` → Zed），只有几个真正看不出含义的缩写（`agy`）放进一张 5 行的别名表，其余一律首字母大写。新命名空间不需要改代码。
2. **Host 改动**：暂不动。来源层已在客户端实现，等 Host 透传 `source` 时只需替换 `sourceOf` 的实现。
3. **行内标签**：只保留例外标记（`modelInvocable === false` → 「仅用户」），普通技能不加标签。
4. **折叠状态**：记住，存 `localStorage`（键 `dsh.skillsPanel.prefs.v2`，存折叠集合 + 当前打开的那一组）。
5. **「全部折叠 / 全部展开」按钮**：不做。

### 8.0 第一版实现被指出的问题（全部已修）

首版交付后连续被指出三轮问题，每一轮都修在了根因上：

| 轮次 | 现象 | 根因 | 现在 |
| --- | --- | --- | --- |
| 1 | 6 行标题 + 一大片空白，"可读性也很差" | 默认全部折叠，等于把技能藏起来 | **默认展开最大的命名空间分支**（现在会展开 Lark，28 项） |
| 1 | 没有设计图里的层级感 | `来源数 ≤ 1` 就整层跳过 | 两个及以上来源必然渲染来源层 |
| 2 | 默认进去就是 sh 展开，**点不动** | `toggleGroup` 关闭分支后仍把它记为 `active`，`isOpen` 又把它打开——**关闭分支这个操作在逻辑上不可能生效** | 拆出纯函数 `togglePlan`：点开着的分支就是关闭，并用 `NO_OPEN` 哨兵区分"我关掉了"和"我还没选过" |
| 3 | `Sh (47)` 里只列 25 项；合计 84/109 | 三个独立 bug：名字的段数正好等于所在层时被丢弃；递归只传子段导致无限递归；剥掉作者前缀后不认叶子 | 全部修掉，现在 **109/109** |
| 3 | 两个都叫 `Lark` 的分支 | `sh-lark-*` 和 `lark-*` 的短标签天然撞名 | 撞名的分支升级成完整路径 `Sh › Lark` |
| 3 | `Sh` 这个 47 项的根分支 | `sh-` 是作者前缀不是分类 | 整层都是 `sh-` 时把前缀剥掉、下层提升为顶层；**递归剥离**，所以 `sh-zed-lsp-*` 仍会分出 `Lsp` |
| 3 | 中文界面里出现 `bundled` | 来源提示直接渲染了根路径 | 固定短提示（只读 / 随工作区），完整路径进 `title` 悬停 |
| 4 | **点已展开的分支无反应**（点 Lark 没反应、点 Antigravity 有反应） | `togglePlan` 拿 `prefs.active` 判断"是否点在开着的分支上"，但**默认展开的分支并不在 `prefs.active` 里**（它是渲染时算出来的 fallback）。所以点它永远匹配不上，被当成"打开它"，看起来就是没反应 | `togglePlan(prefs, id, displayed)` 接收**界面上真正显示为打开的那个分支**；组件把算出来的 `activeGroup` 传进去 |
| 4 | 两个 `Lark` 撞名修成了 `Lark › Lark` | 撞名兜底无条件用"作者前缀 + 自身"，前缀为空时就退化成自己套自己 | 有可用父名就用父名（`Zed › Lsp`），否则才用作者前缀；并挡住 `X › X` 这种自我重复 |

第 4 轮的教训值得记下来：前三轮我都只测了**纯函数**，而"点不动"是**渲染层**的问题——纯函数怎么测都是对的。所以补了 `design/test-render.mjs`：用带状态的 React mock 真的把面板渲染出来，点一下，再断言 DOM 里 `aria-expanded` 和展开出来的行。这类 bug 只有这样才抓得到。

### 8.1 分组算法

**L1 来源层**：三个桶 —— **系统内置 / 用户安装 / 当前工作区**。

来源的判定有两个坑，都是实测踩出来的：

1. **客户端拿不到 `process.env`**。首版用 `DSH_HOME`/`USERPROFILE` 拼根路径，在浏览器里全是 undefined，结果所有技能都会被判成 bundled。所以改成**纯从 `path` 反推**：路径里出现 `<前缀>/.agents/skills` 或 `<前缀>/.dsh/skills`，那个 `<前缀>` 就是技能所在的父目录。
2. **一个路径只能说明"父目录是谁"，不能说明"这是家目录还是检出目录"**。所以：观察到的父目录按**用户**读，会话的 `cwd` 按**工作区**读，两边都注册成根，最后靠最长前缀匹配裁决。没有会话时（拿不到 `cwd`）才让观察到的父目录兼任项目根，否则所有技能会挤进一个桶。

随应用发布的技能（`resources/runtime/office-skills` 里的 office-*、asar 内置的 dsh-badge）不在任何根里，落 `bundled` 桶。本机实测：`用户安装 105` + `系统内置 4`。

> 工作区桶目前只在真的放了 `.agents/skills` / `.dsh/skills` 时才非空，这是符合预期的——DSH 的项目根就是"最近的有 `.git` 的祖先，没有则用 cwd"，客户端不遍历祖先目录（代价太高），直接用会话给出的 `cwd`。

**L2 命名空间层**：**按 `-` 分段递归成树**，深度由数据自己决定，不预设层数。

- `lark-approval` 的段在 `lark-` 就结束了 → `lark` 分支下的**叶子**，不会为了它开一个 `approval` 分支。
- `sh-zed-lsp-config` / `sh-zed-lsp-install` 共享 `sh-zed-lsp` → 自然分成 `zed › lsp` 两层。
- 某个段只出现一次就不成分支，名字留在上一层当叶子——避免"只有一个子节点的标题"。
- 集合里每个名字都以 `sh-` 开头时，`sh-` 是作者前缀而非分类，构建时先剥掉，否则会冒出一个装着三分之一技能的 `Sh` 分支。
- 分支标签只取**父级还没展示过的那一段**（`sh-zed-lsp` 在 `zed` 下面显示为 `Lsp`），几个真正看不出含义的缩写走 5 行别名表（`agy` → Antigravity）。

**兜底**：某层里没有共同前缀的名字进该层的「其他」，永远渲染、永远在最后。

### 8.2 行与交互

- `SkillRow` 用原生 `<details>/<summary>`：折叠态一行三段（名字 / 例外标签 / 单行省略描述），展开态显示完整描述、「使用时机」、指令文件路径和「查看 SKILL.md」。
- **默认打开哪一组**：`largestGroupId(sections)` 选成员最多的、且不是兜底组的那个命名空间组。全部都折叠的面板会被读成"空列表"，所以永远至少开一组。若用户上次留下过选择（`localStorage` 里的 `active`）且该组仍然存在，就用用户的。
- 搜索态下忽略折叠状态：全部分组展开、命中行也展开，让结果一次看全。
- 搜索展开行时传 `open: true`；非搜索态不传 `open`，让用户自己开合——避免"能点但点不动"的受控属性。
- 分组头是 `<button aria-expanded>`，chevron 用 `transform: rotate(-90deg)` 表达折叠；二级标题缩进 14px 表示层级。
- 折叠状态是 `Set<string>`，组 id 形如 `userAgents/ns:lark-`；localStorage 不可用时静默降级为仅本次会话有效。

- 默认只展开一个分支，且是最大的那个
