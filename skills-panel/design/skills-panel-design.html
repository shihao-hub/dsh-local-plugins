落地路径

分组怎么算出来（三级，成本递增）

  • L1 来源 —— 完全动态，但当前机器只有一个桶。后端发现阶段就给每个候选打好了 source 和 rank（六档：project-dsh / project-agents / custom / user-dsh / user-agents / bundled），注册表靠它们合并多个 provider。但 skills/list 只透传 5 个字段，source 被截掉了。而且本机六个根里只存在 ~/.agents/skills 一个 —— 所以这一层现在只会得到「用户安装 105」，渲染时应当直接跳过。
  • L2 命名空间 —— 完全动态，能自动长出 47%。实测 design/verify-auto-cluster.py：不提任何类目名，按 - 切段统计前缀覆盖，自动得到 lark-* 28、sh-agy-* 8、redis-* 7、sh-zed-* 6，共 49/105。剩下 56 项里，既有命名不统一的（sh-windows-* 只有 3 个、sh-sublime-* 只有 2 个，凑不成簇），也有一批刻意不带命名空间的基础技能（code-review、tdd、grilling 等 23 个）。纯动态到此为止，拿不到 100%。
  • L3 别名表 —— 静态，但只有 8~12 行。只为把前缀翻译成人话（sh-zed- → 「Zed 编辑器」）。建议放进 <dshHome>/skills-panel.groups.json，你改配置就能改分组名，不用碰代码。
  • 长期解：SKILL.md 的 frontmatter 支持任意 metadata。让 Host 读 metadata.category 并透传，分类就由技能自己声明、随生态演化。属于 Host 改动，列为第二步。

需要你拍板的细节

五件小事

  • L3 别名表放哪：写死在 client.js，还是放 skills-panel.groups.json 让你自己能改？建议后者。
  • 要不要顺手推 Host 改动：给 skills/list 补 source / provider / rank。本机只有一个根，不做也能用；做了以后"项目技能 / 全局技能"才分得开。建议先客户端、Host 留第二步。
  • 行内标签：现在只有「仅用户」。建议不给普通技能加标签，只留例外标记。
  • 折叠状态记忆：切走再回来保持折叠，还是复位？建议记住。
  • 「全部折叠 / 全部展开」按钮：建议砍掉——分组本来就少，逐组点击更便宜。

确认后我按 B 方案改 client.js：只动 CSS 常量、字典和两个新的分组纯函数，不碰 apply 的注册结构。所有技能一条都不会少，只是默认不再全部铺开。
