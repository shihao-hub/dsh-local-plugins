# RUNBOOK：`dsh web` 设置点了没反应 / 自动跳回原值

> 适用症状：**设置改完刷新就还原、点「深色」自己跳回「跟随系统」、界面无任何报错**。
> 结论先行：这**不是** DSH 的 UI bug，而是 profile 的**设置文档被别的程序占着**，DSH 的原子写入被 Windows 拒绝（`EPERM`）。
> 完整根因与证据见 [dsh-settings-document-lock.md](./dsh-settings-document-lock.md)。

## 0. 30 秒判定

```powershell
# free = 现在能写；HELD = 有人在占，设置一定写不进去
foreach ($p in @("$env:USERPROFILE\.dsh\profiles\web\cordis.patch.yml","$env:USERPROFILE\.dsh\profiles\desktop\cordis.patch.yml")) {
  $state = 'free'
  try { $fs=[System.IO.File]::Open($p,'Open','ReadWrite','None'); $fs.Close() } catch { $state='HELD' }
  "{0,-5} {1}" -f $state, $p
}
```

## 1. 谁在占？（按文件反查，免安装）

```powershell
# Restart Manager：给出持有句柄的进程（通常是编辑器/IDE 主进程）
# 脚本见知识库条目 65 的 Step 1，或报告第六节
```

判定要点：

| 反查结果 | 含义 | 处置 |
|---|---|---|
| `app="Zed"` / 其它编辑器主进程 | **它的某个 agent 会话或缓冲区把配置目录当上下文** | 去该编辑器的 **Agent 面板删掉引用了 `.dsh` 路径的会话**；只是关标签页没用 |
| 自己的服务进程 | 自杀式占用 | 检查应用是否漏关句柄 |
| 杀软/索引器 | 占用时有时无 | 加白名单；或改完设置等几秒重试 |
| `(no holder reported)` 但仍写失败 | 不是持有问题 | 查目录 ACL / 只读属性 / 磁盘错误 |

## 2. 对症处置（按优先级）

1. **删掉那个 agent 会话**（本例根因）。删完重启编辑器、复查第 0 步仍为 `free`。
2. **编辑器缓冲区**：把该文件打开成可见标签再 `Ctrl+W` 关闭；若下次启动又回来，说明会话状态在恢复它。
3. **孤儿持久化状态**（有句柄、无标签）：备份编辑器的 `.db`/`-wal`/`-shm` 后删掉对应 `editors` 记录（Zed 的 `db.sqlite` 里就有这种行）。
4. **零容忍改动**（用户不接受动编辑器配置时）：接受"编辑器开着时设置写不进去"，必要时先退出编辑器再改设置。
5. **不要**为此改 `restore_on_startup` 之类的编辑器配置 —— 那是权宜，且会改变使用习惯；先按第 1 步定位触发者。

## 3. 插件侧兜底（已实现，见 `rider-theme`）

- 配色只在**深色基座**上挂载 → 不会出现"深色 token 叠在浅色基座上"的半套状态；
- 检测到**偏好写入被拒**（以设置文档回读为准）时，本客户端自行维持深色基座，**点「深色」不会再弹回「系统」**，且**不会反复去写那个写不进去的文件**；
- 设置行内按状态给出提示：你确实选了浅色 / 写不进去（本页自维持深色，其它设置项仍会丢）/ 连基座都没保住。

## 5. 记忆点

- **「文件能写」≠「文件能被替换」**：直接覆写常常成功，只有 temp + rename 才暴露占用。
- **HTTP 200 ≠ 写入成功**：看响应信封与 `revision` 是否递增。
- **句柄是内核概念**：任务管理器、编辑器界面都看不见，只能按文件反查。
